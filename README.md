# owndapp

この端末にある開発プロジェクトをまとめて管理し、依存パッケージの脆弱性を確認して、優先度の高いものから対応を進めるローカルツールです。

フォルダからアプリを見つけてカタログに登録し、チェック・修正・再チェックまでの対応を記録できます。Node.jsを導入済みの開発者向けに、ターミナルから起動してブラウザで使います。

## できること

- **探して登録する**：ローカルフォルダを探索し、見つかったアプリを選んで登録。深いフォルダも探索でき、途中で止めて再開できます。
- **脆弱性をチェックする**：依存パッケージを既知の脆弱性データベースに照会し、優先度・修正版・対策メモを確認できます。
- **対応を記録する**：調査中・対応中・再照会待ちなどをアプリごとに記録し、修正後のチェックで解消を確認します。
- **パッケージから探す**：`Brotli`などの名前の一部や版から、利用しているアプリを探せます。
- **管理するものを絞る**：不要になったアプリをアーカイブし、今後探さないフォルダを除外できます。

初回ホームで、作業用のエディタ・ターミナルも任意で登録できます。後から「設定・使い方」で変更できます。macOSとWindowsの対応アプリで、登録したプロジェクトを開けます（Windows実機の選択・起動は未検証）。

## 必要な環境

- macOS、またはWindows（フォルダ選択・パス入力。標準ダイアログは実機未検証）
- Node.js **24.14以降**とnpm

アカウント登録は不要です。ソースを取得して、そのフォルダで起動します。

```sh
git clone https://github.com/elephantnode/owndapp.git
cd owndapp
```

Gitを使わない場合は、GitHubの「Code」→「Download ZIP」で取得し、展開したフォルダを開いてください。

## インストールと起動

macOSでは各コマンドを1行ずつ実行し、結果を確認してから次へ進みます。Windowsは[PowerShellでの導入手順](docs/windows.md)を参照してください。

```sh
npm run doctor
npm audit --package-lock-only --audit-level=high
npm ci --ignore-scripts --include=dev
npm audit signatures
npm run build
npm start
```

初回の`doctor`は、依存パッケージとビルド結果がないため終了コード1になります。この2項目だけなら次へ進めます。Node.jsなどの問題がある場合は先に直してください。依存の検査や署名検証に重大な指摘・失敗が残る場合は、結果を確認してから進めてください。

起動したら、ブラウザで **http://127.0.0.1:4310** を開きます。

2回目以降は`npm start`で起動できます。停止するには、起動したターミナルで`Ctrl+C`を押します。

詳しい手順は[はじめる](docs/getting-started.md)、更新・バックアップ・困ったときは[運用ガイド](docs/operations.md)を参照してください。

## 画面の使い方

1. **フォルダを追加する**：「ホーム」から「アプリを追加」へ進み、プロジェクトを置いている親フォルダを指定します。macOS・Windowsでフォルダを選択できます。パスの直接入力にも対応します。
2. **アプリを登録する**：検出した候補から、管理したいアプリを選んで登録します。用途・タグの入力は任意です。
3. **脆弱性をチェックする**：登録後の案内からチェックへ進み、外部へ送る情報を確認して開始します。
4. **優先度の高いものから修正する**：「脆弱性と対応」で対策メモを確認し、エディタなどで修正します。対応状況はアプリごとに記録できます。
5. **もう一度チェックする**：修正後に再チェックし、検出されなくなった問題の解消を確認します。
6. **今後の管理を減らす**：継続して管理しないものはアーカイブし、今後探索しないフォルダは除外します。元のソースファイルは移動・削除しません。

「登録したアプリ」は一覧・フォルダ別で表示でき、利用中とアーカイブを切り替えられます。特定のパッケージを調べたい場合は「依存検索」を使います。検索対象外のアプリは「依存の検索範囲」から確認し、選んだ対象だけ読み直せます。

操作の詳細は[使い方ガイド](docs/usage.md)を参照してください。

## チェックできる依存パッケージ

| 種類 | 読み取る主なファイル |
| --- | --- |
| Node.js | npm・Yarn・pnpmのlockファイル |
| PHP | `composer.lock` |
| Python | `poetry.lock`・`uv.lock`・`Pipfile.lock`・`requirements*.txt` |
| Rust | `Cargo.lock` |
| Go | `go.mod` |
| Ruby | `Gemfile.lock` |
| Java（Maven） | `pom.xml`（直接依存のみ） |

アプリの検出に対応する言語と、依存の解析に対応する形式は異なります。未読・未対応・読み取り失敗は区別して表示します。検索0件や検出0件でも、未確認の構成まで安全と判定するものではありません。対象形式の詳細は[実装済み機能](docs/features.md)と[依存解析の対応範囲](docs/dependency-coverage.md)を参照してください。

owndappはパッケージの更新を自動で実行しません。チェックはローカルに記録された依存が対象で、公開先に修正が反映されたかは別途確認してください。

## データの保存と外部への送信

探索・登録したカタログと対応記録は、この端末の`.owndapp/`に保存します。バックアップは、サーバーを停止してから保存先フォルダ全体をコピーします。[バックアップと復元の手順](docs/operations.md#バックアップ)を参照してください。

脆弱性を照会するときは、確認画面を経て、パッケージの種類・名前・版をOSV（`https://api.osv.dev`）へ送ります。プロジェクト名・パス・ソースコードは送りません。

owndapp自身のnpmパッケージ取得はTakumi Guardを経由します。登録したアプリにも個別に設定できます。設定方法と通信の範囲は[Takumi Guardの使い方](docs/takumi-guard.md)を参照してください。
