# 開発課題と未対応項目

更新日: 2026-10-26。利用者向けの導入・操作は[README](../README.md)、現在の詳しい対応範囲は[実装済み機能](features.md)を参照してください。この一覧は課題の整理で、すべての実装や公開時期を約束するものではありません。

## 公開前に決めること

- MITライセンスを採用。配布先は `https://github.com/elephantnode/owndapp`。
- GitHubの非公開脆弱性報告を有効化し、実際に報告窓口へ進めることを確認する（現在は無効）。
- 公開に含めるGit履歴と個人情報を確認し、初回CIの結果を確認する。詳細は[公開準備](release-readiness.md)。

## 未対応の機能・解析

- Gitの未コミット・未追跡・競合、追跡先との差、remoteの鮮度、実ランタイムの版、依存グラフ（どの直接依存から間接依存に至るか）の表示。
- bun・Deno・Go・Ruby などの依存の読み取り、`requirements*.txt` の `-r` の参照先や範囲指定の解決、semverの範囲での検索、依存の定期的な自動読み取り。
- WordPress のプラグイン・テーマの脆弱性照会（Composer で管理していないものは OSV に載らない）、更新候補の照会、依存の経路（どの直接依存から間接依存に至るか）、照会の自動・定期実行。
- クラウド上の資源・稼働・デプロイ済み版の照会。
- 別チェックアウトを1つのProjectへまとめる編集、既存パスの移動への追従、自由なComponent再編。
- 既定の探索除外（node_modulesなど）の変更、名前やパターンでのフォルダ除外、定期探索、手動プロジェクト登録。

「脆弱性と対応」は既知の脆弱性への対応記録を中心に、再チェックが必要な結果・見つからないフォルダ・除外フォルダ・読み取り失敗への操作をまとめる。未検査・判定できる依存なしを正常と混同せず、対象範囲と件数を表示する。用途・管理状態の未入力は「整理（任意）」として補助表示する。カタログの集計と通常の対応一覧はアーカイブ以外を対象にする。アーカイブで公開先が停止したことにはならない。ローカルでの解消確認と、公開先への修正反映は別に確認する。

境界の印がない親（package.jsonだけの親など）は、配下のfrontend/backendを別候補のまま表示する。workspacesの対応は単純なパスと `*` / `**` のパターンが中心。複雑なglob、動的設定、tool固有の構文は後続対応。supabaseの専用設定やWordPressプラグインヘッダーなど、構成案にある検出のすべては実装していない。

## 確認が残る環境

- 導入検証はmacOS / Apple Siliconで実施。Intel Mac、他OS、全Node.js版の確認は未完了。
- 公開配布URLからの新規取得と、Finderの実ダイアログ操作は、新規導入検証では未確認。
- 署名検証でのTUF鍵取得の警告と直接取得へのフォールバックは、[導入検証記録](install-verification.md)を参照。

日付や対象コミットの異なる検証結果は、現在の全環境での動作や安全性の保証として扱わない。


## Windowsの第一段階（2026-10-26）

パス直接入力による起動・探索の実装を追加。macOS専用のフォルダ選択、Finder表示、エディタ/ターミナル登録起動はWindowsでは提供しない。既存のmacOS機能は維持する。

Windows実機での新規導入・ビルド・起動・停止/再起動、ドライブ文字・UNC共有・長いパス、ACL・ジャンクション、SQLiteの保存と復旧、Guardの設定書き込みとレジストリ検査は未検証。実機受け入れ前にWindows対応完了とは扱わない。詳細は[Windows手順](windows.md)。
