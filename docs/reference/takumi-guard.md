# Takumi Guardを使う

owndapp自身は、プロジェクトの `.npmrc` に `registry=https://npm.flatt.tech/` を設定している。グローバル設定は変更しない。`ignore-scripts=true`、版の固定、lock・脆弱性・署名の確認、テストは引き続き必要。

## 登録プロジェクトへの設定

プロジェクト詳細の「パッケージ取得の保護」で設定状態を確認し、「Guardを設定…」から変更内容と送信先を確認して適用する。直下のnpm向け設定を対象とし、既存設定がある場合は元の内容を同じフォルダの `.npmrc.owndapp-backup-*` に保存する。バックアップには元の認証情報が含まれる場合があるため、Gitに追加しない。

既存の独自レジストリや解釈できない設定は上書きせず、理由を表示する。Yarn独自設定やnpm以外の形式は自動設定の対象外。npm・pnpmを直下で実行する場合の支援であり、子フォルダやCIはそれぞれの設定を確認する。アプリから一括適用や依存更新、インストールは実行しない。

「設定済み」はファイル上の状態を示す。環境変数、コマンドの指定、ユーザー設定、キャッシュ、直接URLや別の取得先によってはGuardを通らない。アプリは実効設定やブロック動作を通信で検査しない。実際に更新するターミナルで `npm config get registry` を確認する。npm標準レジストリのURLが記録されたlockは、通常の `replace-registry-host=npmjs` 設定でGuard向けに置き換えて取得する。`replace-registry-host=never` など取得先の置換を変える指定があれば、Guardを経由しない場合がある。接続できないときは自動で別の取得先へ切り替えない。

## 保護の範囲

匿名利用はアカウントやトークンなしで、Guardが悪意を検出した公開パッケージの取得をブロックする。パッケージ名・版など取得要求に必要な情報がGuardへ送られる。後日判明した問題の通知は匿名利用にはない。通知が必要なら公式ガイドのメール登録や組織向け設定を別途検討する。トークンはリポジトリに保存しない。

Guardのブロックと既知の脆弱性検査は別の役割。すべての未知のマルウェアや不具合を防げるわけではない。既に取得した依存が安全になったとは扱わない。lockは削除・一括置換せず、既存のintegrityと版を保持する。独自の取得先・private scopeは個別設定を優先する。公開やログイン時は公式ガイドのnpm本来のレジストリの指定を確認する。

設定適用中は別のエディタやプロセスで `.npmrc` を編集しない。適用直前にも変更を確認するが、確認と差し替えの間の同時編集を完全には防げない。

## 戻すとき

更新作業を止め、現在の `.npmrc` とバックアップを手元で比較する。適用後の別の編集を消さないよう、Guardのregistry行だけを元の内容に戻す。元ファイルがなければ追加した行だけを除く。lockにGuardのURLが記録されている場合、設定を戻すだけでは取得先が戻らないことがある。lockを削除して作り直さず、変更前のGit差分と公式手順を確認する。
