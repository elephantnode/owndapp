# 初心者向けメニューと利用の流れ

## 目的

インストール後、メニューの意味を推測せずに、ローカルフォルダの追加から登録・チェック・個別対応・維持対象の整理へ進める。用途・タグ・管理状態の整理をチェックの前提にしない。

## メニュー

| メニュー | 役割 |
| --- | --- |
| ホーム | 初回の開始操作、通常利用のチェック待ち・未完了の対応・中断した探索の案内 |
| アプリを追加 | 探索フォルダを選択またはパス入力し、検出候補を選んで登録 |
| 登録したアプリ | 利用中／アーカイブ。保存場所と一覧から管理 |
| 脆弱性と対応 | チェック、優先度順の個別対応、メモ、再チェックによる解消確認 |
| 依存検索 | パッケージ名から使用アプリを検索。部分一致を既定とし、完全一致と版指定も可能 |
| 設定・使い方 | 6段階のガイド、インストール・更新、探索・除外フォルダへの入口、エディタ・ターミナル |

主要な6項目は折りたたまない。狭いウィンドウでもラベルを表示する。アーカイブは「登録したアプリ」の中で切り替える。依存検索は利用者の要望により主要メニューへ独立させる。

## 初回と通常利用

1. インストール：README／docs/getting-started.mdの手順。画面内では使い方ガイドから再確認できる。Node.js導入済みのmacOS開発者が対象。
2. ホームの「フォルダからアプリを探す」から親フォルダを追加。
3. 候補を確認して「選択した候補を登録」。登録後は「登録したアプリの脆弱性をチェック」を案内。「登録してチェック」なら送信確認へ直行する。
4. チェックを始める前にOSVへ送る情報を確認。開始後は「脆弱性と対応」へ移動し、進捗・結果を確認できる。アプリ詳細からの再照会は詳細に留まり、フォームの入力を保つ。
5. 優先度が高いものから対策メモ／エディタで修正。対応状況を記録し、再チェックして解消を確認。
6. 継続して管理しないものはアーカイブ。今後探さない場所は探索除外。登録解除は別の選択として確認する。

通常利用のホームは、未完了の対応と未検査・古い結果・不完全なチェックを案内する。ホームは概要と次の操作を示す場所とし、対応画面を複製しない。取得失敗を「対応なし」「安全」と扱わず、再取得できる。

## カタログの階層

「登録したアプリ」で「一覧／フォルダ別」を切り替える。既存のフォルダ階層・折りたたみ・フォルダ単位の選択を維持する。階層は実際の保存場所に基づき、画面操作でソースを移動しない。探索フォルダの設定と、登録済みアプリの階層は別の概念。

対応画面はフォルダ階層を超えて優先度順に並べる。同じアプリの記録をどちらからも参照する。

## 整理の区別

- アーカイブ：記録を残し、通常のチェック一覧から外す。戻せる。
- カタログから外す：owndappへの登録を解除する。元ソースは削除せず、取り外した記録を既存のremovalsへ保持する。
- 探索から除外：今後の探索範囲から外す。登録済みアプリから除外するときは「このフォルダ内の登録済みアプリもカタログから外す」を選べる。既定では外さない。

除外と登録解除は既存APIを順に実行する。登録解除に失敗しても除外設定は保存済みであることを明示し、再試行時は現在の登録を読み直す。全体を単一トランザクションとする変更は行わない。パス直接入力から追加した除外フォルダ内の既存アプリは、案内からカタログで確認・解除できる。

## 互換性と分担

内部のhash（#attention/#catalog/#discover/#dependencies/#archive/#settings）と旧#queueの別名を維持し、#homeを追加する。保存データや既存の対応記録の移行は不要。

事前コミットbb6067c。Claude CodeはHomeView/UsageGuideの新規2ファイル、Codexはナビゲーションと既存画面・テスト・ドキュメントの統合を担当。既存APIと部品を使い、新規依存や新しい外部送信を追加しない。

## 実装・検証結果

5つの常時表示メニュー、初回/通常利用ホーム、登録後のチェック案内、設定内の6段階ガイド、フォルダ別表示、除外時の任意の登録解除を実装した。Node.js 24.14.0で166テストとブラウザ9件、型検査・ビルドが合格。幅900/768/390/360pxを含む既存操作、初回・通常利用のホーム、旧#queue、詳細での対応状況、アーカイブ/復帰、除外後の登録解除失敗・再試行、ソースファイルの保持を確認。スクリーンショットは架空データの隔離環境で更新。

実プロジェクトの脆弱性再照会・依存更新、新規依存、DB移行、ユーザーの起動中サーバー停止は行っていない。公開URL・ライセンス等の既存の配布準備事項は別途必要。
