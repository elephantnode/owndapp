# カタログ・発見追加のワイヤーフレーム

更新日: 2026-10-19
状態: 構成と操作の設計案。画面コード・配色・フォントは未実装・未決定。

## 1. 利用者と操作の整理

これまでの会話で決まったこと:

- 主な利用者は、自分の過去の開発プロジェクトを整理する開発者。
- 主な端末はMacのブラウザ。狭いウィンドウでも使えることを重視する。
- カタログの主操作は、対応が必要なプロジェクトを検索・抽出し、根拠を確認すること。
- 発見追加の主操作は、探索候補を確認し、選択したプロジェクトを登録すること。
- 一覧は脆弱性・更新候補などの対応情報を優先し、用途・技術構成も併記する。
- 登録後は追加分に絞ったカタログへ移動し、用途やタグを整理する。診断は自動開始しない。
- アプリの起動・停止とクラウド照会は初版に含めない。

主操作の成功状態:

| 操作 | 成功状態 |
| --- | --- |
| 検索・絞り込み | 一致件数と、なぜ一致したかが表示される |
| 追加 | 登録件数が確定し、追加分の一覧へ移動する。全体表示へ戻せる |
| 整理 | 用途・タグ・管理状態が保存され、一覧で確認できる |
| アーカイブ | 通常一覧から外れ、アーカイブ一覧に理由付きで残る |
| 診断 | 実行中・部分成功・失敗が区別され、結果から根拠を確認できる |

## 3. レイアウトと操作

以下の枠内は領域と操作の構造。色・サイズ・最終文言を指定するものではない。

### カタログ: 広いウィンドウ

```text
┌──────────────┬───────────────────────────────────────────────────────┐
│ [製品名]     │ [画面名]                                 [発見・追加] │
│              ├───────────────────────────────────────────────────────┤
│ [要対応]     │ [検索..............................................] │
│ [カタログ]   │ [要対応 / 全件] [技術] [管理状態] [アーカイブを含む]   │
│ [発見・追加] │ [条件と件数]                         [並び順]         │
│ [アーカイブ] ├──┬────────────┬──────────┬────────┬────────┬───────────┤
│              │選│ 名前・構成 │ 要対応   │ Git    │管理状態│ 最終確認  │
│              ├──┼────────────┼──────────┼────────┼────────┼───────────┤
│              │□ │ [名前]     │ [問題]   │ [変更] │ [状態] │ [日時]    │
│              │  │ [技術構成] │ [未確認] │        │        │           │
│              ├──┼────────────┼──────────┼────────┼────────┼───────────┤
│              │□ │ [名前]     │ [問題]   │ [変更] │ [状態] │ [日時]    │
│              │  │ [技術構成] │ [未確認] │        │        │           │
│              ├──┴────────────┴──────────┴────────┴────────┴───────────┤
│ [設定]       │ [選択時の操作バー]                    [ページ切替]   │
└──────────────┴───────────────────────────────────────────────────────┘
```

表は比較用とし、各行の名前を詳細リンクにする。選択チェックボックスと詳細へのリンクを分ける。列幅が狭いときはGit・管理状態・日時の順に補助情報を行内へ折り畳み、要対応と名前を優先する。

既定の並び順案は、未対応の重大な脆弱性、その他の脆弱性、サポート期限、更新候補、確認が必要な項目の順。実装済みの診断結果だけを評価する。未確認項目は別の件数として常に表示し、既知の問題がないことと混同しない。

要対応画面は同じカタログの保存済み条件として実装する案とし、別の一覧ロジックを作らない。診断未実装の段階は、管理状態が未設定・確認が必要な項目を中心に表示する。

検索欄は初版では名前・説明・用途・タグ・パス・技術名の部分一致。詳細フィルターで依存ecosystem、パッケージ名、版、宣言値か記録された版かを指定する。初版では検索演算子の学習を必須にしない。

依存の一致は「記録された版に一致」と「宣言から該当する可能性」を分ける。結果行から根拠ファイルと取得日時へ進める。

### 発見・追加: 広いウィンドウ

```text
┌──────────────┬───────────────────────────────────────────────────────┐
│ [ナビ]       │ [画面名]                                              │
│              ├───────────────────────────────────────────────────────┤
│              │ [探索パス..................................] [探索] │
│              │ [除外条件の要約]                         [条件編集] │
│              │ [進行状況・探索範囲]                    [キャンセル] │
│              ├───────────────────────────────────────────────────────┤
│              │ [候補件数] [新規 / 登録済み / 要確認] [候補内検索]   │
│              ├──┬────────────────┬─────────────┬─────────────────────┤
│              │選│ 候補・パス     │ 構成        │ 登録状態            │
│              ├──┼────────────────┼─────────────┼─────────────────────┤
│              │□ │ [親候補]       │ [複数構成]  │ [新規] [内訳]       │
│              │  │  └[Component]  │ [技術]      │ [親とまとめる]      │
│              ├──┼────────────────┼─────────────┼─────────────────────┤
│              │□ │ [候補]         │ [技術]      │ [関連候補あり]      │
│              ├──┴────────────────┴─────────────┴─────────────────────┤
│              │ [一部未探索・失敗した場所]                [再探索] │
│              │ [選択数]                            [選択分を登録] │
└──────────────┴───────────────────────────────────────────────────────┘
```

候補は既定で未選択。workspaceの親を選ぶと所属Componentをまとめて登録する。独立したGitルートなど曖昧な候補は内訳で確認する。親子の二重登録を許さない。

登録済みの候補は選択不可にし、既存の詳細リンクを表示する。関連チェックアウトは別物として登録できるが、同じProjectの追加SourceLocationとして関連付ける選択肢も用意する。

探索結果は完了するまで確定扱いにしない。探索をキャンセルした場合は「確認済み候補のみ」と表示し、その候補は選択・登録可能にする。未完了の探索を完了と表示しない。

登録直前にパスの存在と重複を再確認する。登録操作は重複送信に耐え、選択集合をトランザクションで保存する。パス消失・競合がある場合は登録を確定せず、問題行を示して選択を保持する。

追加完了後は追加操作IDで絞ったカタログへ移動し、件数と「全件に戻る」を表示する。登録時の管理状態は「未設定」。用途、タグ、状態は詳細または選択時の操作から編集する。

### 狭いウィンドウ・スマートフォン幅

```text
カタログ                         発見・追加
┌─────────────────────────┐     ┌─────────────────────────┐
│ [ナビ] [製品名]  [追加] │     │ [ナビ] [画面名]         │
├─────────────────────────┤     ├─────────────────────────┤
│ [検索.................] │     │ [探索パス.............] │
│ [要対応 / 全件] [条件] │     │ [条件]           [探索] │
│ [条件要約・件数・順序] │     │ [進行状況] [キャンセル] │
├─────────────────────────┤     │ [候補区分・候補内検索] │
│ □ [名前]        [状態] │     ├─────────────────────────┤
│   [技術構成]           │     │ □ [候補名]       [状態] │
│   [要対応] [未確認]   │     │   [パス・技術]          │
│   [最終確認]           │     │   [内訳・根拠]          │
├─────────────────────────┤     ├─────────────────────────┤
│ □ [名前]        [状態] │     │ □ [候補名]       [状態] │
│   [技術構成]           │     │   [パス・技術]          │
│   [要対応] [未確認]   │     │   [内訳・根拠]          │
├─────────────────────────┤     ├─────────────────────────┤
│ [選択操作] [ページ]    │     │ [選択数]        [登録] │
└─────────────────────────┘     └─────────────────────────┘
```

構成上の境界案は、1200px以上で表の全列、768〜1199pxで補助情報を折り畳み、767px以下で縦のリストとする。最低幅360pxを想定する。固定ナビ幅で内容を押しつぶさず、中間幅ではナビを縮小する。

詳細は別ページに置く。検索条件・ページ位置を保持して戻れるようにする。確認したい問題のリンクから詳細内の該当箇所へ移動する。

### 詳細ページの情報順序

1. 名前、用途、パス、管理状態、編集操作。
2. 要対応・未確認の一覧と根拠へのリンク。
3. 構成、Git、依存関係、配置設定のタブ。配置設定には「クラウド上の実態は未確認」を明示。
4. 診断と判断の履歴、メモ。

Gitの単なる未コミット変更は、脆弱性と同じ重大度で警告しない。別の状態情報として表示する。

### 一括操作とアーカイブ

- 全選択は現在ページを対象とし、対象件数を示す。初版では検索に一致した全件への暗黙の操作をしない。
- タグの一括追加は既存タグを置き換えない。削除は別の操作とする。
- アーカイブ時は対象件数と理由入力を示す。アーカイブ済み一覧から復帰できる。
- 診断の一括実行は初版B以降の機能。ローカルと外部照会を分け、追加直後には自動実行しない。
- アーカイブ後は選択を解除し、通常一覧の表示件数を更新する。用途や履歴は保持する。

## 4. 画面の状態と回復操作

| 状態 | 必須度 | カタログ | 発見・追加 |
| --- | --- | --- | --- |
| 通常 | 必須 | 検索条件・件数・対象範囲を表示 | 候補・根拠・登録状態を表示 |
| 読込中 | 必須 | 200msを超えたら行に合わせた読込表示。既存結果は残す | 探索済み件数・現在範囲・経過時間を表示。総数不明で割合を捏造しない |
| 初回・空 | 必須 | 未登録の理由と発見追加への導線 | パスの入力方法を示す。0候補時は探索範囲・除外の見直しへ誘導 |
| 絞り込み0件 | 必須 | 条件を保持し、解除する操作を表示 | 候補区分と候補内検索の解除を表示 |
| 失敗 | 必須 | DB/APIなど原因に応じて再試行。診断失敗を一覧全体の失敗にしない | 無効パス・権限不足・読取不能を該当パスに表示 |
| 部分成功 | 必須 | 取得できた項目を表示し、失敗したチェックだけ再実行 | 読めた候補を残し、未探索・上限・失敗件数を示す |
| 競合 | 必須 | 別タブの編集を版番号で検出。入力を残して再読込・再適用を選ぶ | 探索後の既存登録・ファイル変更を再確認して対象行を更新 |
| 接続断 | 必須 | ローカルAPI停止と外部ネット未接続を区別。未保存入力は保持し、保存済みと表示しない | APIに届かないときは新規操作を止め、再接続してジョブ状態を確認 |
| キャンセル | 必須 | 診断の完了済み結果を保持 | 確認済み候補だけ登録可能。途中結果であることを明示 |
| 成功 | 必須 | 更新内容をその場で確認可能にする | 追加分に絞った一覧へ移動。登録件数と全件への導線を残す |

外部ネットが切れていてもローカル探索・整理は可能。APIとの接続断時は書込を自動再送せず、再接続して確定済みかを確認する。表示上の成功はAPIから確定応答が得られた場合だけとする。

### キーボード・アクセシビリティ

- 検索・フィルター・チェックボックス・リンク・操作ボタンをTabで順に操作できる。
- 行全体をクリック可能な要素にせず、名前リンクと選択を分離する。
- 絞り込み・探索完了・登録結果は適切なライブ領域で通知する。探索中の細かな件数変化を毎回読み上げない。
- 狭い幅のナビ・フィルターを閉じたら起点にフォーカスを戻す。ダイアログ内のフォーカスを管理する。
- 状態は色だけに依存せず、文言とアイコンを併用する。
- パスは折返しと全文確認を可能にする。省略で別の場所を取り違えさせない。

## 5. 実装前に詰める点

構成案として採用した仮置き:

- 一覧を中心に、診断の根拠を1回の操作で確認する。
- 保存する検索条件は初版では画面内と戻る操作の維持まで。自由な保存済みビューは後続。
- 探索は利用者による明示実行から始める。定期自動探索は後続。
- 順位や期限の閾値は設定可能にする前提で、初期値は実装段階で決める。

未決定だが、今回の低忠実度ワイヤーフレームの作成を妨げない事項:

- 色・明暗テーマ・アクセント・フォント・情報密度の最終調整。
- 実装時のCSS方式。React/Viteなどの技術構成は構成案の段階。
- 動きの設計。探索の進行・状態変化を伝える以外の演出は現在の案に含めない。
- 検査の鮮度・期限の基準と、初期の外部脆弱性情報源。

画面実装前にこれらを確認し、必要なトークンを定義する。この文書はMarkdownの形状案であり、動作するUIや検証済み画面ではない。
