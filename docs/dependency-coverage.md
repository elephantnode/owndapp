# 依存解析の対応範囲

npm・Yarn・pnpm・Composer・Pythonの形式は[実装済み機能](features.md)を参照。ここではRust・Go・Ruby・Mavenの取り込みと、未対応の範囲を記載する。

## Rust（Cargo.lock）

2026-10-26 実装。Cargo.lockのパッケージ名・版・sourceを静的に読み取り、Rust（OSV ecosystem: crates.io）として依存検索・詳細・照会の既存フローに接続する。Cargoの実行、インストール、ダウンロード、プロジェクトの書き換えは行わない。

- version 3 / 4、およびversionのないv2形式（package内checksumで識別）に対応。v1、判別不能、未知のversionは未対応として残す。`version = 2`という表記は受け付けない。
- 複数版、直接・間接、改名、dev/build/target、既知のworkspaceメンバーと継承した依存を扱う。build/targetの実行条件は確定しない。宣言とlockが一致しない場合は不一致を表示する。
- workspaceの共通lockはメンバーを重複して読まない。読み取ったメンバーのCargo.tomlも変更検知に含める。探索で登録された構成要素とルートのファイルを対象とし、新しい未登録の構成は再探索が必要。
- crates.ioの標準index/sparse sourceだけを公開由来とする。別レジストリ、Git、ローカル、不明な取得元は区別し、OSVへの照会対象から除く。照会は既存の送信確認を経る。
- lockは解決済み依存の記録。features・targetの有効化、インストール済み・配布済み・実際に使用中であることは確認しない。パッチやソース置換の設定を実行評価しない。

v1/v2にversion欄がないこととchecksumの形式は [Cargo公式スキーマ](https://github.com/rust-lang/cargo/blob/master/crates/cargo-util-schemas/src/lockfile.rs)、明示versionの扱いは [Cargo 1.85の読み取り実装](https://github.com/rust-lang/cargo/blob/rust-1.85.0/src/cargo/core/resolver/encode.rs) に基づく。

## Go（go.mod）

2026-10-27 実装。`go.mod` の `require` を静的に読み取り、Go（OSV ecosystem: Go）として接続する。goコマンドの実行・ダウンロード・ビルドは行わない。

- `// indirect` の付いた行は間接依存、それ以外は直接依存として記録する。テスト用かどうかは区別しない（本番/開発は「不明」）。
- Go 1.17 以降の `go.mod` は、ビルドとテストに必要なモジュールをすべて記載する（module graph pruning）。それより前、または `go` の指定がない `go.mod` は「直接依存のみ」と表示し、記載のない間接依存は照会しない。
- `replace` は反映する。別のモジュールへの置き換えは置き換え先の名前と版を記録し、ローカルのパスへの置き換えは「ローカル」として送らない。`exclude` は依存として扱わない。
- `go.sum` は読まない（使われなくなったモジュールのチェックサムも含むため）。`go.work` は未対応として表示する（各モジュールの `go.mod` は登録済みの構成要素として読むが、`go.work` の `replace` は反映しない）。
- 取得元（GOPROXY・直接のリポジトリ・GOPRIVATE）は `go.mod` に記録されないため「レジストリ（lockに記録なし）」とし、照会の対象に含める。非公開のモジュール名も送られる。
- Go本体の標準ライブラリの脆弱性は照会しない（`go` の指定は最低限の版で、実際のツールチェーンの版ではないため）。

## Ruby（Gemfile.lock）

2026-10-27 実装。`Gemfile.lock` を静的に読み取り、RubyGems（OSV ecosystem: RubyGems）として接続する。BundlerとRubyの実行、Gemfile（Rubyのコード）の評価は行わない。

- `GEM` の `specs` を依存として記録する。`remote` が rubygems.org だけなら公開、別のサーバー1つなら「別のレジストリ」、複数のサーバーが混在する古い形式はどのgemがどこ由来か分からないため「取得元不明」として送らない。`GIT` は Git、`PATH` はローカルとして送らない。
- `DEPENDENCIES` にあるgemを直接依存とし、括弧内の制約を宣言範囲として記録する。Gemfileのグループ（development・test）は評価しないため、本番/開発は「不明」になる。
- `nokogiri (1.16.0-arm64-darwin)` のようなプラットフォーム別の行は、版（`1.16.0`）だけにして1件にまとめる。
- Gemfileがない、または `DEPENDENCIES` の一部が `specs` にない場合は「宣言と不一致」とする（別のプラットフォーム向けのgemのこともある）。Gemfileだけでlockがない場合は「lockなし」とする。

## Maven（pom.xml）

2026-10-27 実装。`pom.xml` の直接依存を静的に読み取り、Maven（OSV ecosystem: Maven、名前は `groupId:artifactId`）として接続する。Mavenの実行・ダウンロード・プラグインやプロファイルの評価は行わない。

- `pom.xml` は lock ではなく宣言のファイルで、推移的な依存は書かれていない。そのため常に「直接依存のみ」と表示し、推移的な依存は照会しない。Mavenが解決した一覧（`mvn dependency:tree` の出力など）は読まない。
- 版は、依存の `<version>`、`<properties>` と `${project.version}` などの組み込みのプロパティ、`dependencyManagement` から決める。親POMがプロジェクト内にあれば（`relativePath`、既定は `../pom.xml`、最大5階層）、そのプロパティと `dependencyManagement` も反映し、親POMの変更も検知する。
- リポジトリから読み込むBOM（`<scope>import</scope>`）、プロジェクト外の親POM、範囲指定（`[1.0,2.0)` など）、解決できないプロパティによる版は決められないため、「版の固定なしを含む」と件数を示し、それらは照会しない。
- `<scope>test</scope>` は開発、`<optional>true</optional>` は任意、それ以外は本番として記録する。`system` スコープはローカルのjarとして送らない。`build`（プラグイン）・`profiles`・`reporting` の中の依存と、コメントアウトした依存は読まない。
- 取得元（Maven Central・社内リポジトリ・ミラー）は記録されないため「レジストリ（lockに記録なし）」とし、照会の対象に含める。
- Gradle（`build.gradle`・`build.gradle.kts`・`gradle.lockfile`）は未対応として表示する。

## 版の並びと修正版

修正版を選ぶときの版の比較は、エコシステムごとの規則に従う。RubyGemsは `Gem::Version`（`1.0.0.rc1` は `1.0.0` より前）、Mavenは `ComparableVersion`（`alpha < beta < milestone < rc < snapshot < 正式版 < sp`、`1.0` と `1` と `1.0-ga` は同じ）、Goはsemver（先頭の `v` は除く）。

## 未対応の範囲

SwiftPM、Go workspace（`go.work`）、Gradle、NuGet、Bun/Denoの既知のマニフェスト・lockがルートや登録済み構成要素にある場合、未対応として記録する。これらのパッケージは検索・照会されない。すべての言語やファイル名を網羅する判定ではない。コード内の使用、OSやNode本体に組み込まれたライブラリは検索対象外。

対応形式と同居する場合も一部未確認と表示し、不完全な照会で過去の脆弱性や対応記録を解消扱いにしない。検索画面には読み取り実施・解析できた記録・未対応形式を含むアプリの件数を表示する。検索0件は使用なしの証明ではない。

既存記録には反映されないため、依存情報を読み直してから「依存検索」でBrotliなどを検索する。実プロジェクトの読み直しや外部への照会は今回の検証では行っていない。


## 検索対象外・未確認のアプリを確認する

「依存検索」の「依存の検索範囲」から「検索対象外・未確認のアプリを確認」を開く。

1. 未読、未対応形式あり、読み取りの問題、lockなしで絞り込む。名前・パスでも絞り込める。最初はアーカイブ以外を表示する。
2. アーカイブしたアプリを調べる場合は「アーカイブも含める」を選ぶ。依存検索の結果自体は以前からアーカイブを含む。
3. 読み直すアプリを選び、「選択したN件の依存を読み取る」を押す。1ページ25件で、全選択は表示中の読み取り可能なアプリだけが対象。絞り込みやページを変えると選択を解除する。見つからないフォルダ・除外フォルダ内のアプリはこの操作から選べない。
4. 読み直し後は、最後に実行した検索とパッケージ一覧を更新する。フォームを編集しただけでは検索条件を変更した扱いにしない。読み取り操作に失敗した場合は選択を残し、そのまま再試行できる。各ファイルの読み取り問題は結果と詳細に残る。

状態と件数は最後に保存した読み取り記録に基づく。ファイルの常時監視はしない。Rust・Go・Ruby・Mavenなどの解析形式を追加した後は、以前「読み取り済み」だったアプリでも「すべて」に切り替えて対象を選び直すと、新しい形式も取り込める。未対応形式は読み直すだけで解析できるようになるとは限らない。既知の形式だけの対応で、未対応が0件でも全構成を網羅したという意味ではない。

この操作はローカルの依存記録だけを更新し、OSV照会・パッケージ更新・インストールを始めない。アーカイブや公開・管理状態も変更しない。
