## 目的と決定済みの範囲

過去に作ったローカルのプロジェクトを発見・カタログ化し、保守が必要なものを見つけ、脆弱性への対応とアーカイブ判断を進める。

- 言語を限定せず、ブラウザから利用するローカルアプリとする。
- 初版はローカルのソース、設定、Git、依存関係を扱う。
- アプリの起動・停止機能は作らない。
- 次段階で各種クラウドを照会し、ローカルの情報と関連付ける。

## 初版の利用フロー

1. 探索する親フォルダと除外条件を登録する。
2. 設定ファイルやGitからプロジェクト候補を発見する。
3. 候補の構成とパスを確認し、選択してカタログへ登録する。
4. 用途、タグ、管理状態、関連するプロジェクトを整理する。
5. ローカル診断と、必要に応じて外部照会を伴う依存関係の診断を実行する。
6. 横断検索から影響するプロジェクトを抽出し、対応や判断を記録する。
7. 保守を止めるプロジェクトは、理由を記録して論理アーカイブする。

## 管理する情報

| 分類 | 主な項目 |
| --- | --- |
| 基本 | 名前、説明、用途、タグ、ローカルパス、関連プロジェクト |
| ソース | Gitリポジトリ、チェックアウト、ブランチ、変更、最終コミット |
| 技術構成 | 言語、フレームワーク、ランタイム、パッケージ管理方式 |
| バージョン | 宣言された要件、ロックファイルで解決された版、確認できた実環境の版 |
| 依存関係 | パッケージ名、版、直接・間接依存、開発・実行用の区別、判定元 |
| 配置設定 | 推定されるプロバイダー・サービス、設定ファイルの場所 |
| 診断 | 脆弱性、更新候補、サポート期限、チェック実行履歴 |
| 管理 | 未設定・計画中・開発中・テスト・検証・運用中・保留・完了・中止・アーカイブ、理由、メモ、次の対応 |

ランタイムの指定値、ロックファイルの値、ホスト上のツールの版、実際の配置先の版を同一視しない。取得できない値は不明とする。

最終コミット日時、ファイルの変更日時、owndappでの最終確認日時は個別に保持する。古いコミットだけで放置や不要と判定しない。

## 検出と登録

- 指定された探索範囲だけを調べ、依存物、ビルド成果物、キャッシュ、仮想環境を除外する。
- Git管理のないプロジェクト、複数の言語を使う構成、モノレポにも対応する。
- Node.js、Python、PHP、Go、Rustなどの設定ファイルを検出対象とする。詳しい診断の対応範囲は言語・管理ツール別に明示する。
- VueやNext.jsなどのフレームワークと、Lambdaなどの配置先を別の属性として扱う。
- 同じリポジトリの複数チェックアウトを関連候補として提示する。自動で統合せず、個々のローカル変更を保持する。
- シンボリックリンクによる範囲外の探索と循環を防ぐ。
- 再探索では新規・既存・パス不明を区別する。見つからなくなっただけで登録を削除しない。
- 自動検出の根拠を表示し、手入力による補足・訂正を保持する。

## 診断と脆弱性対応

- Gitは未コミット、未追跡、競合、追跡先との差分などを確認する。自動でfetch・pull・pushしない。リモートとの比較の鮮度と追跡先未設定を区別する。
- パッケージは名前とバージョンで全プロジェクトを検索できるようにし、間接依存も対応する範囲で対象にする。
- 外部照会を伴う検査はローカル検査と区別し、照会先、送信する情報の種類、実行日時を確認できるようにする。
- 脆弱性の取得元、識別子、影響する版、修正版、重大度、検出日時を保持する。
- 対応状況は未対応・調査中・対応済み・対象外などで記録する。対象外の判断には理由を残す。
- 対応済みという記録と、再診断で検出されなくなった事実を区別する。
- 状態は未確認・実行中・完了・失敗・対象外を区別する。一部失敗でも他の結果は表示する。
- 問題が検出されなかった場合は検査範囲を示す。未知の脆弱性や未検査の構成まで安全とは判定しない。
- 各結果に取得日時と根拠を持たせ、新しい脆弱性情報に対する再確認状況が分かるようにする。

## アーカイブ

初版のアーカイブはカタログ上の状態変更とする。対象ファイルの移動・削除、Git操作、クラウド資源の停止・削除は伴わない。

- 通常一覧では非表示にでき、いつでも復帰できる。
- 理由、判断日、再開に必要なメモを残す。
- 横断検索には含められる。診断結果の検索と、新たな診断の実行は区別する。
- アーカイブ状態と、公開・稼働・配置状況は別に扱う。

## 技術構成案

- 画面: React + TypeScript + Vite。部品は shadcn/ui（Tailwind CSS v4・Radix UI、2026-10-19に標準CSSから移行）
- ローカルAPI: Node.js + TypeScript + Hono
- 保存: SQLite。設定、登録情報、観測結果、診断履歴、判断記録を保存する。
- 実行制御: バックグラウンドのジョブ待ち行列。多重実行を防ぎ、同時実行数、タイムアウト、キャンセルを扱う。
- 検出・検査: 共通処理と、言語・パッケージ管理方式ごとのアダプターを分離する。
- 将来のクラウド照会: ローカル検査とは別のアダプターとして追加する。

```text
ブラウザ
   │
ローカルAPI ─ カタログ・検索・管理状態
   │
ジョブ制御 ─ 検出 / Git / 言語別診断 / 将来のクラウド照会
   │
SQLite ─ 登録情報 / 観測結果 / 診断履歴 / 判断記録
```

主なデータ単位は Project、Component、SourceLocation、Repository、Observation、CheckRun、Finding、Decision とする。将来は Deployment と CloudResource を追加し、1プロジェクトと複数環境・資源を関連付けられるようにする。

Observationには対象、取得方法、根拠ファイルの位置、確認日時を保持する。設定由来の推定と外部照会で確認した事実を区別し、手動の訂正を再検出で上書きしない。

ローカルAPIはループバックに限定し、他のWebページからの不正な呼び出しを防ぐ。検査コマンドは実行ファイルと引数を限定し、設定ファイルを実行可能なコードとして読み込まない。プロジェクトのスクリプト実行、依存物のインストール、自動修正は初版に含めない。秘密情報の値をカタログやログへ収集しない。

## 開発段階と完了条件

### 1. 発見とカタログ

探索、候補確認、登録、検索、タグ、メモ、論理アーカイブを実装する。複数言語、Gitなし、モノレポ、重複候補、パス移動を扱えることを確認する。

### 2. ローカル診断

Git、ランタイム指定、依存関係を取得する。対応する言語・ロックファイルごとの範囲を明示し、未対応を正常と表示しない。特定のパッケージと版を使うプロジェクトを横断検索できることを確認する。

### 3. 保守と脆弱性対応

脆弱性照会、更新候補、サポート期限、確認履歴、対応記録を追加する。オフライン、照会失敗、部分的な結果、古い診断結果を区別できることを確認する。

### 4. クラウド照合

対象プロバイダーと参照範囲を決めてから、読み取りによる資源・配置状況の照会を追加する。ローカルにソースが見つからない資源も未紐付けとして扱う。クラウド照会の権限や認証はこの段階で設計する。

## 次に具体化すること

1. 画面は明るいニュートラルと緑、システムフォント、最小限の動きで実装した。
2. React/TypeScript/Vite、Node.js/Hono、SQLiteを採用し、探索→候補確認→登録→カタログ検索・整理・アーカイブを実装した。
3. 次は実プロジェクトで検出の範囲を確認し、Git・ランタイム指定・依存関係の診断を追加する。

この設計案は将来の機能も含む。現在の実装範囲は[実装済み機能](features.md)、検証済み範囲は[検証記録](verification.md)を基準とし、実プロジェクトへの診断を行ったものとは扱わない。
