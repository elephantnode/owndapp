## 1. Product purpose

ローカルの開発プロジェクトを発見し、対応する依存形式の既知の脆弱性を確認し、対策と再チェックを一つの作業画面で進める。

## 2. Primary user

自分が過去に作ったアプリを、Macのブラウザと狭いウィンドウで管理する開発者。

## 3. Three to five principles

1. 要対応情報を優先する。用途と技術構成は同じ一覧で参照できる。
2. 未確認を正常扱いしない。診断範囲と根拠を表示する。
3. 登録後はチェックへ案内する。用途・タグ・状態の整理は任意で、あとから行える。
4. 観測と判断を分ける。別チェックアウトや静的な配置設定を実環境の事実と混同しない。

## 4. Success metric for the surface

用途・タグ・開発状態を入力せずに、フォルダから登録・チェック・対策確認・再チェックへ進める。対応記録と履歴を維持し、未検査・判定不能・古い結果を正常と混同しない。

## 5. Out of scope

- アプリの起動・停止。
- 初版でのクラウド照会。
- 自動更新・自動修正・ソースの移動や削除。
- 既知の脆弱性以外の安全性保証、本番デプロイ済み版の証明。

## 6. Learned constraints

- 2026-10-19 — 明るく簡潔で、表と文字を中心にする。色とフォントは任意選定可。動きは最小限。
- 2026-10-19 — 一覧は要対応情報を優先し、追加後は追加分に絞って整理する。主な端末はMac。
- 2026-10-19 — UIは shadcn/ui（Tailwind CSS v4・Radix UI）で構成する。部品は `src/components/ui/` に置き、見た目は既存トークンに合わせる。shadcn CLI は検査前に依存を入れるため使わず、依存は docs/dependency-policy.md の手順で追加する。選択肢は Native Select でmacOS標準の操作を保つ。

- 2026-10-25 — Node.js導入済みの開発者向けローカルツール。通常アプリ化やApple Developer Programへの参加は前提にしない。
- 2026-10-25 — 「要対応」と「対応キュー」を「対応する」に統合。用途・タグ・管理状態の整理は任意とし、検査や対策の前提にしない。

- 2026-10-26 — 主要メニューは「ホーム／アプリを追加／登録したアプリ／脆弱性と対応／設定・使い方」を常時表示。「登録したアプリ」の中で利用中・アーカイブ・パッケージ検索と一覧・フォルダ別を切り替える。初回から登録・チェック・対応へ進む流れを優先し、メニューの階層と保存場所の階層を分ける。

- 2026-10-26 — 依存検索を下位画面に隠さない。主要メニューの独立項目とし、6項目構成にする。Brotliのような部分名で探せることを優先し、名前の部分一致を既定とする。

- 2026-10-27 — 依存検索の入力欄は「パッケージ名」1つにまとめる。一致方法の選択と版の欄は置かず、版は `名前@版`、完全一致は一覧から名前を選んで行う。記録パッケージの一覧は検索語に連動させ、独自の絞り込み欄を持たない。読み直し対象の絞り込みは「依存の検索範囲」の折りたたみ内に限る。

- 2026-10-26 — 詳細の対応状況はプロジェクト単位。画面上部に全体の状態と操作を1か所置き、脆弱性ごとの変更操作は並べない。個別記録から集約し、通常の全体変更では個別メモを保持する。

- 2026-10-26 — Windowsの第一段階はパス直接入力。サーバーOSの能力に応じてネイティブ操作を隠し、Macの既存操作を維持する。Windows実機未検証を実装済みの模擬テストと区別する。
